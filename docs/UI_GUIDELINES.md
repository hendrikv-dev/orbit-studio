# UI Guidelines

These are current workspace-specific implementation heuristics. They are subordinate to the UX,
accessibility, scientific-honesty, and evidence principles in `docs/ORBIT_CONSTITUTION.md`.

Explorer should feel like a premium interactive data visualization, not aerospace software.

- Visualization owns the screen.
- Search remains primary.
- Explore begins with recognizable educational collections; Complete Catalog preserves access to
  every record without making raw catalog order the default.
- Constellations are explored as systems first and as individual spacecraft second.
- Persistent UI should be minimal.
- Secondary controls collapse until needed.
- Inspectors appear contextually.
- Object details communicate identity, purpose, and key facts in Overview, with orbit, architecture,
  provenance, and catalog fields grouped under Orbit & data.
- Display controls are grouped by Objects, Collections, Reference Layers, and Visualization.
- Preserve capability without permanent chrome.
- Avoid permanent left-side tool clutter unless a view genuinely requires it.

Playground should feel like manipulating an orbit, not managing a catalog.

- Default to one satellite and one orbit.
- Show simple controls first.
- Hide advanced controls behind Advanced / Orbital Elements / Expert Mode.
- Keep "Add Satellite" obvious.
