# Tracker NASA meteor data

The sole runtime dataset is `src/data/meteors/showers.json`, deterministically generated by `node scripts/build-nasa-meteor-showers.mjs` from `nasa-snapshot.json` and separate first-party `tracker-model.json`. `--check` compares bytes; no network, old catalogue, generated legacy fallback, or runtime acquisition path exists. Twelve identities/display aliases are retained; unconsumed `iauNumber`/`parent` are omitted.

## Rights, acquisition and update policy

All five documents were directly acquired from their official NTRS download URLs on 2026-10-11 (the earlier four during preflight). Metadata states Public distribution and Public Use Permitted; the 2026 forecast and 2021 overview additionally specify US-government work. Exact IDs, URLs, SHA-256 of the acquired PDFs, publication/table locations, rights and frames are in `nasa-snapshot.json`. No complete paper, third-party diagram, or image is bundled. The retained material is the minimal numerical table subset attributed to the publications, including Jopek/Jenniskens for the nomenclature table. This is an evidence-backed public-use determination for that subset, not a claim that every item in every NASA publication has identical rights.

Updates are deliberate, offline, reviewed changes to the input snapshot. Do not refresh values silently. Retain checksums of the acquired source and inspect tables visually: PDF extraction can lose negative signs and red/blue revision meaning. Source loss does not trigger a legacy fallback. Invalid/missing inputs fail generation. Acquired research PDFs and rendered verification pages stay outside the repository.

## Exact field mapping

CP = [20110016582](https://ntrs.nasa.gov/citations/20110016582), NASA/CP-2011-216469, Jopek/Jenniskens Table 1, printed p10 / PDF p22. Its caption explicitly specifies **J2000.0 for both solar longitude and geocentric RA/Dec**. No coordinate transformation is applied to the stored radiant anchors. Source RA/Dec are not apparent observer Alt/Az and have no fabricated error bars.

F = [20250009524](https://ntrs.nasa.gov/citations/20250009524), 2026 forecast Table 3, PDF p8. Seven current showers have rows, not eight. Peak UT and ground visual maximum ZHR are adopted verbatim. Spacecraft flux columns elsewhere are not used as observer rates.

H = [20200000049](https://ntrs.nasa.gov/citations/20200000049), handbook Table 2, printed p51 / PDF p63. Activity spans, geocentric speeds and otherwise uncovered calendar peak dates/ZHR come from matching named rows. Its erroneous Lyrid RA96 is **not used**; CP supplies all radiant coordinates.

M2/M3 = [20170004446](https://ntrs.nasa.gov/citations/20170004446), forecasting methods Tables 2/3, PDF pp8/9. Population index `r` is adopted, not mass index. CAP/STA/NTA speeds are explicitly at 100 km. ORI/LEO/STA/NTA typical ZHR comes from the matching named row, with LEO peak component20 rather than the base4. **No Bp/Bm or solar-longitude peak is adopted**: radar-size profile qualifications and unspecified longitude frame are not silently transferred to the visual model.

O = [20210017329](https://ntrs.nasa.gov/citations/20210017329), “Some annual meteor showers”, PDF p17. CAP/STA/NTA activity bounds and STA/NTA typical peak dates only. The slide's annotated ETA2023/LEO2033 rates are not substituted into 2026.

## Explicit normalization and uncertainty

The normalization year is fixed **2026**, not the machine's current year. Calendar-only peaks use noon UTC on the published date; that time is a deterministic convention, **not a published minute-precision prediction**. Activity starts use UTC00:00 at the first date. Ends use UTC00:00 following the inclusive last date; the internal inclusive-longitude predicate includes that mathematical endpoint. QUA uses Dec28,2025 through Jan9,2026 around its 2026 peak. Astronomy Engine2.1.19 `SunPosition().elon` converts these dates/UT to apparent solar longitude, equinox of date; output rounds to nine decimal places for deterministic storage, not physical precision. The source **did not publish those activity solar-longitude endpoints**.

The unchanged annual `SearchSunLongitude` recurrence model uses the normalized peak longitude. Only seven2026 peak times are independently forecast. Later/earlier years are typical recurrence estimates, not NASA-issued annual forecasts/outburst predictions; rates and activity boundaries also inherit annual variability. User-visible limitations retain the distinction. Numerical equivalence is deliberately not forced where the source changes a value.

## Radiant model and narrow frame correction

Published forecast times are UT. The browser's UTC `Date` is used as their civil-time
representation; UT1-UTC can differ by up to 0.9 seconds. This is below the source's
minute resolution and is not a claim of sub-second peak timing accuracy.

`radiantEquatorialOfDate` takes raw CP J2000 RA/Dec -> fixed J2000 ecliptic -> drift by current J2000 solar longitude minus **CP anchor longitude** -> fixed J2000 equator -> true equator of date. The directional drift invariant remains the existing `lambda_radiant - lambda_S` model, not a fitted per-stream measured drift. No inference about newer-table equinox is necessary.

Investigation showed the old code fed Astronomy Engine's `Ecliptic()` (true ecliptic **of date**) into `Rotation_ECL_EQJ()` (fixed J2000). The replacement uses `Rotation_EQJ_ECL()` explicitly. The observing-potential map previously combined unprecessed raw coordinates with of-date sidereal time and omitted drift; it now consumes the same helper. These are documented frame corrections required to use the explicit source, not astronomy-pipeline redesign. Sky continues consuming the nightly radiant track through the existing production path.

## Deliberately unchanged model

Nightly and worker planning keys retain their existing ownership but now include
the authoritative NASA snapshot date in `TRACKER_PLAN_MODEL_VERSION`. A derived
plan must not advertise the retired transcription/frame model identity.

Widths0.35/1/9/8/12/2/5/25/25/1/1.2/0.5days are separately retained first-party coarse core FWHM values in code order. They are not NASA/IMO measurements. The85% core/base mix, edge rate1,0.9856degrees/day conversion, limiting-magnitude calibration, horizon reduction, sporadic calibration, observer/date/equipment state, ranking algorithm and UI are unchanged. NASA CMOR B coefficients have **not** been adopted or silently converted. Source-backed ZHR/r/activity/position corrections can nevertheless change recommendations, dates, rates and brightness-character copy; the external comparison records them rather than calling them equal.

## Verification boundary

Source rows and published dates provide independent input evidence. Fixed-frame and inverse-rotation tests establish transformation/model conformance, not observational radiant accuracy. Coarse radiant drift, zenith attraction and atmospheric visibility remain limitations; no physical-phone AR validation is claimed. Complete gates and numerical comparisons are recorded in the final external review package, never inferred from this document.
